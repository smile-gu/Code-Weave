## 2. 最小策略：来源召回、整组确认、保守合并

### 召回

沿用overlaps：相同path、side、sha256的代码引用闭区间有交集即形成潜在重复边。不要求rule/title/category/trigger/suggestion文本相同，也不以这些字段相似度自动判断重复。

对原始已验证Finding构建来源重叠连通分量，顺序固定为PASS_ORDER、candidateId；仅处理至少两项的分量。连通只是召回关系，不是“同Bug”的传递性证明。base/final/diff不跨坐标系猜测转换；没有代码引用或同Bug只跨side但无交叠的情况本版可能漏召回，记录为范围限制，不引入AST/Embedding/新依赖。

现有DedupDecision上限32项。分量超过32项时按固定顺序切为最多32项的块，块内再次按重叠关系求分量；不创建跨块自动合并，遗漏比较写限制说明。不能截断后假称原分量全部完成。输入规模不因去重放开已有数量、Token、字节和时间门禁。

### 语义确认

沿用DedupDecision：candidateHandles、sameRootCause、sameTrigger、sameFix、rationale，不新增模型输出字段。请求提供组内所有原始已验证Finding（含claim、reasoningSummary、suggestion、来源和disposition）；不得将模型正文当系统指令。

三个布尔均表示“组内所有项”，不是“存在两项相同”。模型须比较：

- 根因：同一导致缺陷的机制/变更，而非仅相同文件或共同异常名称。
- 触发：必要前置条件与执行路径等价；不同输入/权限/并发条件不能只因结果相似就合并。
- 必要修复方向：修复同一根因的动作相容；表达差异和附加可选测试建议不等于必要修复不同。

rationale须具体说明以上比较及范围，拒绝仅写“相同/同文件”。平台能强制非空、有界及身份正确，但不能确定性证明自然语言语义充分，不新增关键词审查器。任何一项不同或不确定返回false。保留现有恰好本组句柄、无重复/遗漏/额外句柄门禁，禁止模型挑子集或输出新Finding。

本版整组全有或全无：混合组中若有一条不同，整组保留分立，即使其中部分重复。这是有意选择的保守漏合并，不新增自动子组、成对矩阵或传递闭包合并。连通链A-B-C但A与C不同的回归必须拒绝整组合并。后续若要提高混合组召回率，另行设计子组协议。

### 确定性合并

仅已确认sameRootCause/sameTrigger/sameFix全部true且句柄精确匹配的原始组可进入合并。删除trigger/suggestion全文一致作为语义门禁的要求，但不能把merge_group变成无条件可调用的破坏性入口：调用方必须持有本组已校验决策，生产入口和单元测试均覆盖未确认不得合并。

合并前本地校验：同Run/Snapshot、来源/候选/验证身份真实且无重复；原始项均来自本次Pass结果；claimKind与disposition须一致，否则保留分立并写明限制。允许严重程度不同，沿既有确定性主项选择（PASS_ORDER、candidateId），不重算或提升/降低主项等级，不让模型改标题/描述/证据。

保留所有Evidence和代码引用的去重并集、每个原始项的contributions；不把合并后的结果再次当原始输入递归吞并。保留主项原判断，全部成员的原文字段及差异保存在审计记录。最终Result3.0结构及Java/UI合同不变。

容量沿用：Evidence最多16、代码引用最多16、contributions最多32及原序列化字节限制。超限整组不合并、保留原项并给限制，不截断来源、不仅为通过样例扩大合同。模型三true不绕过这些确定性门禁。

## 3. 可追溯依据与确认顺序

每个完成比较的组保存不可变SYSTEM审计Artifact，使用新recordType dedup_decision、recordVersion 1.0，内容至少包含：

- Run/Snapshot/State版本和revision、purpose、模型调用ID、本组句柄与原候选ID。
- 组内原始Finding完整投影及canonical摘要、来源重叠边和固定分组/分块信息。
- 校验后的原始决策（三个布尔和rationale）、平台最终动作MERGED或RETAINED与原因。
- 合并时主项与成员身份、结果摘要；拒绝时保留失败门禁类别。不同等级等原成员差异可从原始投影回放。

复用ArtifactService和State.artifactRefs，不新增位置验证记录类型、不把去重判断当Evidence、不扩validationRecordRefs。Artifact必须FULL且哈希匹配，State引用必须按既有Checkpoint精确确认后才能采用合并，纳入现有完整性检查与压缩引用保护。

Artifact与Checkpoint不是一个原子事务，失确认不合并、不自动重试；未知存储/身份/完整性故障沿原致命路径停止，不能降级成普通“预算不足”。完整审计超出已有Artifact上限时保留分立，写安全有界限制；不可静默截断审计后声称可回放。未比较组用既有Result limitations说明未覆盖范围，原始Pass结果不改。

## 4. 预算与退出

保留去重最多10次模型调用、600秒及全Run费用/Token/调用/时间门禁；两次共享纠错不增加。一次组请求的纠错同样消耗10次额度，不把10组误称保证能完成10组。

仍按固定顺序串行比较，不借用其他Pass额度，不自动付费重跑。明确预算耗尽/上下文放不下/模型有界结构失败：已确认并可审计的合并保留，未比较或未确认组分立，记录limitations。UNKNOWN费用、失确认、取消及原致命故障按原保护处理，不笼统捕获所有异常然后交付假成功。

无来源重叠无需模型比较，不据此声称全局无重复；真实本次五项被召回后预期仅需一次组判断，实际纠错及用量由未来验收记录，不预先承诺真实请求数。
