# 第五轮真实验收后的结构提交纠错补修

2026-10-11。范围：离线核对生产请求、提交与验证纠错流程；本轮额外真实请求 0。保持未暂存、未提交、未推送。

## 事实与归因边界

第五轮真实 Run 在三次结构提交后停止，受控诊断分别指向 claimKind、CODE 引用未知字段、evidenceIds。三条均为 Schema 拒绝，未到引用语义校验或独立验证。原诊断没有具体 Pydantic 校验类型及原值，不能反推第五轮每次究竟是缺字段、非法枚举、空列表还是其他错误，也不能断言完全属于模型责任。

按实际生产 App/Adapter 请求构造的离线红测确认：

1. 被拒绝的结构回复没有进入下一请求。Provider 无服务端会话记忆，字段路径和提交摘要无法替代待修改的答案。
2. 独立验证通过单独原始材料块装配请求；即使反馈写入 State，原 messages 覆盖视图仍会漏掉反馈及拒绝回复。
3. 超过 State 内联阈值的回复仅提供预览和 Artifact 引用；结构提交阶段没有工具，完整拒绝回复不能只依赖模型自行读 Artifact。
4. 反馈仅说明 SCHEMA_INVALID 和首个字段位置，缺少错误类型与合法约束；直接对 JSON 文本脱敏还可能破坏 JSON 引号结构。

以上是已复现的平台缺口，但离线回归不证明它们解释了第五轮的每个原始模型输出。

## 最小修复

复用现有有界回复、State 保存与 Artifact 能力，先保存脱敏后的拒绝回复，再保存受控诊断和反馈。下一完整请求的纠错视图带入完整脱敏回复与反馈；独立验证保留隔离的原始材料。大回复完整内容只作为当前调用流程的 Provider 装配视图，持久 State 仍遵守内联限制；超限回复保存为 SYSTEM model_reply Artifact，不能作为 CODE Evidence。

完整请求仍通过 fit/invoke 计量、Manifest 保存与预算门禁，不通过截断隐藏内容或扩大输入窗口。纠错视图不允许重启重放，压缩/硬预算规则仍能阻断超限请求。

诊断新增最多 8 条 schemaViolations：白名单字段路径、Pydantic 错误类型，以及从平台模型 Schema 提取的类型、枚举、长度、数值或 UUID 模式约束。多余字段只显示占位路径和平台允许字段列表，不显示模型提交的未知名称、原值、异常消息或 ctx。诊断 Artifact 仍只包含受控元数据；脱敏回复属于不可信历史，不是诊断或可信证据。

复用结构化脱敏，保持合法 JSON 可解析；拒绝回复中的身份字段也按普通不可信值处理，其他调用默认保留原有身份字段策略。输入本身不是合法 JSON 时使用保守文本脱敏。

提交指令显式标注 EVIDENCE_FIRST / CANDIDATES_ALLOWED：要报告候选问题，先提交证据并等待平台 ID；候选 evidenceIds 只能引用已确认记录，不能引用同一提交中新建证据。没有受支持候选时仍允许符合范围/覆盖门禁的零 Finding 结果，不强迫产生问题。

两次纠错总额、模型总预算、证据批量原子发布、完整性/存储/取消阻断、哈希/范围/身份门禁均不放宽。不替模型填充 claimKind、不编造 Evidence ID、不自动丢弃非法字段后接受提交。
