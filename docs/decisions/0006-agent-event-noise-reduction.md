# ADR-0006：Claude Code 高频用量事件降噪

- 状态：M4 已采纳
- 日期：2026-08-18

## 背景

真实 Claude Code E2E 在约 21 秒内产生 1569 条 Run 事件，其中 1526 条是 `system/thinking_tokens`。这些事件逐 Token 报告估算增量，前端执行动态已经主动忽略，但它们仍会被写入 NDJSON、通过 SSE 推送并保存在浏览器内存中。

该次 Run 的事件日志约为 1.04 MB。去除中间用量增量后只剩 43 条、约 27 KB，事件数量和存储流量均可减少约 97%。

## 决策

`ClaudeStreamEventMapper` 不再将 `system/thinking_tokens` 映射为平台 `AgentEvent`。它返回空列表，使中间 Token 增量在进入统一事件模型、事实日志和 SSE 之前结束。

Claude Code 的 `result` 终态继续完整映射为 `RUNTIME_COMPLETED` 或 `RUNTIME_FAILED`，原样保留下列最终字段：

- 输入与输出 Token；
- 缓存读取与创建 Token；
- 模型级用量；
- 总费用；
- 执行轮次和耗时；
- 最终状态和失败信息。

因此，本决策只丢弃过程中的重复估算增量，不丢失最终精确结论，也不影响 Runtime 生命周期、工具调用审计、文本消息、Git Diff 或 Maven 验证。

## 选择协议映射层的理由

- 前端过滤只能改善展示，不能降低磁盘、SSE 和浏览器内存压力。
- Run Journal 是通用事实基础设施，不应理解 Claude 专属协议细节。
- 当前产品不展示实时 Token 进度，没有必要引入带计时器和 flush 语义的窗口聚合器。
- `ClaudeStreamEventMapper` 已经负责决定哪些 Claude 原始行值得进入平台事件模型。

## 业务边界

- 保留 `USAGE_UPDATED` 统一事件类型，供未来能够提供低频、有业务价值的 Agent Runtime 使用。
- 若后续产品需要实时费用预警，应新增明确的采样或阈值事件，而不是恢复逐 Token 持久化。
- 若未来需要保存完整 Claude 原始协议，应作为独立、受大小限制的诊断产物处理，不占用 Run 事实事件序列。

## 前端原始事件展示

原始事件视图保留后端稳定英文枚举和事实序号，但不再直接把顶层类型作为用户标题。前端同时读取 `event.type`、`payload.agentEventType`、工具名、调用标识、阶段和日志字节区间，投影为具体中文行为。

事件卡片不再强制展示摘要。标题已经完整表达含义时，只显示标题和底部技术信息；载荷包含任务目标、基准提交、工具对象、变更数量、日志内容或验证结果时，才增加摘要。

该投影只改善可读性，不合并或改写事实事件。未知的新事件类型继续显示原始协议名称，避免版本升级后隐藏排障信息。
