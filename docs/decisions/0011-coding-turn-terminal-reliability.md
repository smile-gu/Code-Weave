# ADR-0011：Coding Turn 终态、取消与恢复可靠性

## 背景

Coding Turn 的状态快照、事件日志和 SSE 分别位于独立文件与传输通道中。它们不具备数据库事务；如果编排器提前发布终态、取消接口提前声称成功，或单份损坏历史阻断整个启动，用户看到的状态就会与真实执行资源不一致。

## 决策

1. 持久化 `CodingTurn` 是当前状态事实源；事件日志保存历史，SSE 只负责通知。
2. 编排器只返回候选结果，应用服务在 Session 操作锁内重新读取 Turn，并按“必要 Session 更新 → Turn 终态 → 终态事件”收敛。
3. 第一个可靠终态胜出。重复收敛或后到取消不得覆盖已有终态，也不得重复生成终态事件。
4. `QUEUED` 可以直接失败，`startedAt` 保持为空。排队事件写入失败、执行器拒绝和 `RUNNING` 保存失败均不启动 Claude Code；文件写入抛错后优先重新读取，区分“写入前失败”和“文件已替换但通知失败”。
5. 运行中取消先登记内存取消请求，再中断执行线程；接口返回当时的真实持久状态。只有已知进程树清理成功才能保存 `CANCELLED`，清理失败使用 `PROCESS_CLEANUP_FAILED` 并持续保护仓库。
6. 清理时暂时清除线程中断标志，完成有界的子进程优先清理和终态持久化后恢复中断标志。
7. Turn 历史读取区分数据损坏、版本不支持和 I/O 故障，并严格核对 Session、Turn、序号与完整文件名。恢复按 Session 隔离；原文件不移动、不删除，其他 Session 继续恢复。
8. 重启遗留的 `QUEUED/RUNNING` 收敛为 `INTERRUPTED`，不自动重跑；已有终态即使缺少终态事件也保持不变。
9. 前端收到终态事件后查询单 Turn 持久状态；活动 Turn 每五秒低频对账。确认失败只显示“尚未确认”，不能伪造业务失败或开放下一轮输入。

## 明确边界

- 当前仍是单机、单 Control Plane 进程和文件持久化；不提供跨文件原子事务。
- 取消请求只存在执行句柄内，不跨重启恢复。
- SSE 允许重放，前端按 `eventId` 去重；本阶段不建设可靠消息投递。
- 服务重启不能证明此前外部进程已退出；不根据不确定 PID 自动杀进程。
- 本决策不包含五阶段事实化、Agent 事件协议统一、自动重跑、自动修复历史或通用孤儿进程管理。

## 结果

### 独立审查收尾约束

- 取消意图必须在终态操作锁内实时读取，并处理等待锁期间新到达的中断。
- 资源阻断与状态写入阻断分别保存；普通失败落盘不能解除资源阻断。Session 保护写入失败时，仍尽力保存清理失败 Turn，重启和提交门禁共同识别该证据。
- 每轮启动后追踪已知后代，正常退出也要经过 `RunProcessResources`，确认父子进程和读取线程释放。清理失败优先于退出事件、日志完成事件和异常收尾错误。
- 前端所有确认入口共享收尾，确认后清除提示并取消连接、请求、退避和对账定时器。

正常完成、取消、排队失败、状态写入失败和重启恢复使用同一套“先确认资源与持久状态、再对外通知”的原则。执行句柄清理与执行阻断分离，状态或资源无法确认时，同一 Session 不得继续启动新任务。
