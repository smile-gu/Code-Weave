## 依据与问题定性

上一轮真实九项同来源组包含五项STATIC_CORRECTNESS/VERIFIED和四项ENVIRONMENT_DEPENDENT/RISK。三次模型回复均尝试只保留五项，违反整组句柄协议，平台拒绝是正确的。即使强行补齐句柄，本地既有claimKind/disposition兼容门禁也会阻止九项合并。

整组保守分立是原冻结稿接受的限制，不是引用或存储回归；但把平台已知不兼容的项放进同一模型比较组，造成不必要的比较与纠错消耗。这是原最小设计的适用性缺口，不能全部归因于模型能力。

## 冻结算法

1. 输入仍为本Run各Pass已验证的原始Finding，不使用模型自行生成的新标签，也不读合并后结果再次聚类。
2. 按精确二元键(claimKind, disposition)进行确定性分区，使用已持久化的枚举值，不改级、不重新分类、不把RISK转VERIFIED。两个字段任一不同即不进入同一比较组。
3. 每个分区内部执行既有来源重叠连通召回。path/side/sha256及闭区间规则不变；不同分区的节点不能成为连通桥。顺序必须是先分区再建连通分量，而非先按全图分块后再分区。
4. 每分区的过大分量沿用32项固定分块、块内重新求连通分量；单项不发送。最后按各比较组最早成员的(PASS_ORDER,candidateId)排序，组内亦用该顺序，避免字母枚举顺序改变预算优先级。不得依赖输入字典顺序。
5. 本次九项应形成五项VERIFIED组与四项RISK组，各自交模型作整组判断。二元键相同只意味着允许比较，绝不意味着同根；仍须sameRootCause/sameTrigger/sameFix对组内全体为true才合并。
6. 跨分区不合并属于确定性合同边界，不当作待模型补救的“未知相似性”。保留原项语义及全部来源。模型不得跨组挑子集/跨组选择句柄；本地merge_group继续重复检查claimKind/disposition一致，不能因预分区而删除防线。

允许同等级分区内不同严重度，仍沿用固定主项。不得新增按severity/category/标题/关键词/模型主张的分区；不得对必要触发或修复做平台语义猜测。
